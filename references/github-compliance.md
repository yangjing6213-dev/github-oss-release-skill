# GitHub compliance

Do not automate Star, Follow, Fork, repetitive repositories, bulk or irrelevant
Issues/PRs/Comments, keyword stuffing, fake engagement, credential theft,
phishing, malware infrastructure, key-generation or license bypass, attacks
without authorization, unauthorized personal data, unlicensed media/code, or
using GitHub as an unapproved large-file host. Do not evade a restriction with
multiple accounts or identities.

For security or dual-use projects, inspect the stated legitimate purpose,
authorization boundary, `SECURITY.md`, and whether the repository supplies
real attack infrastructure. A dual-use label is not an automatic rejection;
missing authorization or harmful capability is a stop condition.

Use current, authoritative GitHub policy sources for platform claims and record
the retrieval date and uncertainty in a local report. Platform policy evidence
does not authorize a write.
